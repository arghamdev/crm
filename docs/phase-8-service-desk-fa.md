# مرحله هشتم — خدمات و SLA (Service Desk)

این مرحله در نقشهٔ راه پروژه تعریف شده بود اما تا اولویت ۱۰ هیچ پیاده‌سازی‌ای نداشت. ماژول جدید روی همان الگوهای لایه‌ای، Scope و Audit بقیهٔ سامانه ساخته شده است.

## پوشش اقلام نقشهٔ راه

| قلم | پیاده‌سازی |
|---|---|
| Case / Complaint | `ServiceCase` با دسته (شکایت، نقص کالا، تحویل، فاکتور، گارانتی، پرسش) و کانال دریافت |
| Triage / Priority | فرم تریاژ: اولویت + مسئول از بین کاربران فعال شعبه؛ تغییر اولویت مهلت‌ها را از زمان ثبت بازمحاسبه می‌کند |
| Service Queue | صفحهٔ `/service` مرتب‌شده بر اساس فوریت SLA، با فیلتر وضعیت، اولویت و «فقط پرونده‌های من» |
| SLA | دو SLA جدا: پاسخ اول و حل. وضعیت‌ها: در مهلت، در خطر (کمتر از ۲۵٪ زمان باقی‌مانده)، نقض‌شده، رعایت‌شده، متوقف |
| Pause Rule | وضعیت «در انتظار مشتری» ساعت SLA را متوقف می‌کند؛ مدت توقف هنگام ادامه به مهلت‌ها اضافه می‌شود |
| Escalation | سطح ۱ هنگام نقض، سطح ۲ پس از گذشت نیمی دیگر از پنجرهٔ حل؛ اقدام «فوری» در کارتابل سرپرست شعبه یا مدیر فروش ثبت می‌شود |
| Root Cause / Corrective Action | برای حل پرونده الزامی‌اند |
| Reopen | فقط با مجوز `Service.Triage` و تا ۱۴ روز پس از بستن؛ پنجرهٔ حل تازه می‌گیرد |
| Customer Satisfaction | امتیاز ۱ تا ۵ و نظر مشتری هنگام بستن؛ میانگین در صفحهٔ صف |
| Notification | ارجاع‌ها به کارتابل اقدامات منتقل می‌شوند (اعلان ایمیل/پیامک هنوز پیاده نشده است) |

## اهداف SLA پیش‌فرض (ساعت تقویمی)

| اولویت | پاسخ اول | حل |
|---|---|---|
| بحرانی | ۱ | ۸ |
| بالا | ۴ | ۲۴ |
| متوسط | ۸ | ۷۲ |
| پایین | ۲۴ | ۱۲۰ |

مقادیر در `ServiceSlaPolicy` قرار دارند. تقویم کاری (ساعات اداری و تعطیلات) هنوز پیاده نشده است.

## چرخهٔ وضعیت

    New → Triaged → InProgress ⇄ WaitingOnCustomer
                        ↓
                     Resolved → Closed
                        ↑__________↓  (Reopen ≤ 14 روز)

## مجوزها

| مجوز | نقش‌ها |
|---|---|
| `Service.Read` | مدیر فروش، سرپرست، کارشناس، مدیرعامل، ServiceAgent |
| `Service.ReadAll` | مدیرعامل (مشاهدهٔ همهٔ پرونده‌ها بدون امکان تغییر) |
| `Service.Create` / `Service.Update` | مدیر فروش، سرپرست، کارشناس، ServiceAgent |
| `Service.Triage` | مدیر فروش، سرپرست (تخصیص، بازگشایی، اجرای ارجاع) |

کاربری که `Service.Triage` یا `Service.ReadAll` ندارد، فقط پرونده‌هایی را می‌بیند که مسئول یا ثبت‌کنندهٔ آن‌هاست. همهٔ Queryها و Mutationها Scope شرکت، شعبه و قلمرو را اعمال می‌کنند.

## یکپارچگی

- ثبت و حل پرونده در Timeline مشتری (Customer 360) ثبت می‌شود.
- Merge/Unmerge مشتری، پرونده‌های خدمات را هم منتقل و بازگردانی می‌کند (فیلد `ServiceCases` در Manifest).
- `ServiceEscalationWorker` هر ۵ دقیقه اجرا می‌شود (`Service:Escalation:IntervalMinutes`). ارجاع در هر سطح فقط یک بار انجام می‌شود و تعارض هم‌زمانی چند Node را Concurrency Token رد می‌کند.

## گام‌های بعدی پیشنهادی

1. تبدیل «شکایت» و «Claim» پرتال نماینده به پرونده خدمات از صفحهٔ بررسی درخواست‌ها.
2. تقویم کاری برای محاسبهٔ SLA در ساعات اداری.
3. اعلان ایمیل/پیامک برای ارجاع و نزدیک‌شدن به نقض.
4. گزارش KPI خدمات (MTTR، درصد رعایت SLA، CSAT) در داشبورد گزارش‌ها.
