# گزارش تحویل اولویت ۹ — گزارش‌ها و تحلیل

تاریخ: ۲۷ سپتامبر ۲۰۲۶ — نسخه آزمایشی با داده نمونه

## نتیجه

دامنه اولویت ۹ بررسی، طراحی و در پروژه موجود ASP.NET Core MVC پیاده‌سازی شد. صفحات Razor، فیلتر HTMX، CSS سازگار با ساختار Tailwind پروژه و JavaScript موجود استفاده شده‌اند. این مرحله Schema جدید یا Migration جدید ندارد.

### موارد اعمال‌شده

- فرهنگ ۹ شاخص با فرمول، منبع، مالک، قاعده زمانی و محدودیت تفسیر.
- نماهای مدیرعامل، فروش، منطقه، شعبه، مالی و شبکه نمایندگان؛ تغییر نما صرفاً ترتیب نمایش را عوض می‌کند.
- فیلتر منطقه، شعبه، قلمرو و بازه تاریخ؛ تاریخ میلادی با مرز روز UTC و حداکثر ۳۶۶ روز.
- Pipeline، Forecast وزنی، فرصت برنده، تبدیل سرنخ، کیفیت پرونده، وصول، سررسید، تحقق هدف و فروش نماینده.
- قیف سرنخ، تفکیک شعب و ریزداده صفحه‌بندی‌شده با تطبیق صورت/مخرج شاخص.
- مجوز مستقل گزارش، CSV، BI و اطلاعات مالی؛ اشتراک دامنه شرکت/شعبه/قلمرو با مجوز داده مبدأ.
- CSV با UTF-8 BOM، خنثی‌سازی Formula Injection، سقف ۵۰۰۰ ردیف، Anti-forgery، no-store و Audit.
- قرارداد JSON با Schema برابر `crm.reporting.v1` و همان محدودیت‌های دسترسی.
- نقش Executive فقط‌خواندنی، کاربر آزمایشی مدیرعامل و گزینه تخصیص این نقش در مدیریت هویت.
- Port مستقل فاکتور مالی نمونه؛ جلوگیری از تکرار Snapshot و مقایسه هدف/عملکرد ناهم‌دوره.
- اصلاح آدرس فرم ایجاد نماینده که قبلاً پارامتر خالی `id=` تولید می‌کرد.
- پیش‌نمایش مستقل قابل تعامل، آزمون‌ها، Workflow تجمعی و راهنمای استقرار/بازگشت.

محیط محلی فقط SDK 8 قابل استفاده داشت و اجرای معمول MSBuild با خطای محیطی متوقف می‌شد؛ بنابراین کد C# و Razor با Roslyn و بسته‌های محلی بازیابی‌شده کامپایل و تست‌ها روی Runtime 8 اجرا شدند. Target پروژه **net10.0** و نسخه وابستگی‌های پروژه تغییر نکرده است. این تأیید سازگاری محلی جایگزین Gate رسمی .NET 10 نیست.

پیام نهایی آزمون‌های اجراشده:

```text
All priority-9 reporting, scope, export, architecture and cumulative behavior checks passed.
CRM_TEST_SQLSERVER is not set; SQL Server persistence check skipped.
All priority-9 reporting, dealer, order, quote, pipeline and web/security checks passed.
```

سناریوهای جدید شامل دستکاری شعبه، تغییر نمای Expert به مدیرعامل، منع مالی برای فروش، دامنه محدودتر مجوز Export، دامنه محدودتر منبع، حذف فاکتور خارج از دامنه یا آینده، کنترل تکرار Snapshot، مانده صفر واقعی، هدف ناهم‌دوره، بازه روز، مخرج صفر، CSV فرمولی و سقف خروجی هستند. WebTests نیز CSRF، HTMX، no-store، تاریخ نامعتبر، ریزداده و فایل دانلودی را پوشش می‌دهد.

## اجرای نمونه

پس از نصب .NET 10 و بازیابی وابستگی‌ها، مطابق README برنامه را اجرا کنید و به `/reports` بروید. برای Seed جدید، کاربر `reporting.ceo` با رمز آزمایشی `Demo@1405` موجود است. روی دیتابیس از قبل ساخته‌شده، نقش Executive را در مدیریت هویت به کاربر مناسب تخصیص دهید؛ برای ایجاد این کاربر، داده موجود را پاک نکنید.

ورودی جاری پیش‌نمایش `index.html` یا `preview/crm-unified.html` است و ورود، منوی مشترک، صفحات اصلی، ریزداده، CSV و JSON را در یک فایل نمایش می‌دهد. نسخه اولیه `preview/crm-priority9-reports.html` فقط پیش‌نمایش جزئی گزارش بود؛ اکنون ورودی اصلی محسوب نمی‌شود. این فایل جایگزین اجرای MVC نیست؛ کنترل امنیت واقعی در سرویس سمت سرور پروژه قرار دارد. جزئیات اصلاح یکپارچگی و نتایج بررسی در `unified-navigation-fix-fa.md` ثبت شده است.

## موارد باقی‌مانده

۱. اجرای `.github/workflows/priority9-quality-gate.yml` روی Commit مقصد و دریافت نتیجه واقعی .NET 10، SQL Server و Chromium.

۲. برای اتصال واقعی BI/حسابداری: تعیین منبع و مقصد، Adapter واقعی، احراز هویت، ETL، تاریخچه و سیاست نگهداری. در این نسخه قرارداد و داده نمونه آماده‌اند؛ Warehouse یا جریان ETL عملیاتی متصل نشده است.

۳. پیش از حجم عملیاتی: جایگزینی خواندن DataSet نمونه با Query/Projection سمت SQL، ایندکس و آزمون حجم. Snapshot تاریخی ثابت، Forecast Accuracy، CDC/SCD و چندارزی در این نمونه اجراشده محسوب نمی‌شوند.

در دامنه نمونه، پیاده‌سازی اولویت ۹ و کنترل‌های قابل اجرای این محیط تکمیل شده‌اند؛ تأیید Production یا سبزشدن CI ادعا نمی‌شود.
