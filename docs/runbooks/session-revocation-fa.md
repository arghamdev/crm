# Runbook ابطال نشست و قطع دسترسی

## ابطال یک نشست

1. از «کاربران و دسترسی ← جزئیات کاربر ← نشست‌ها» نشست هدف انتخاب شود.
2. User-Agent، زمان صدور، آخرین فعالیت و IP Hash با درخواست پشتیبانی تطبیق داده شود.
3. «ابطال» تأیید شود.
4. رخداد `SessionRevoked` و Correlation ID بررسی شود.

## ابطال همه نشست‌های یک کاربر

- برای رخداد امنیتی، وضعیت کاربر به `Suspended` تغییر کند؛ SecurityVersion افزایش، Cache حذف و همه Sessionها Revoked می‌شوند.
- برای تغییر Role/Scope نیز همه Sessionهای قبلی باطل می‌شوند و ورود مجدد لازم است.

## ابطال توسط خود کاربر

در «امنیت حساب»، گزینه «ابطال همه نشست‌های دیگر» اجرا شود. نشست جاری باقی می‌ماند.

## کنترل نتیجه

1. درخواست عادی نشست باطل‌شده باید به Login هدایت شود.
2. درخواست HTMX باید `HX-Redirect: /account/session-expired` برگرداند.
3. دسترسی حداکثر در بازه Validation تعریف‌شده قطع شود؛ نمونه فعلی در هر درخواست اعتبارسنجی می‌کند.
4. در صورت ادامه دسترسی، هماهنگی ساعت Nodeها، Shared Session Store، Cache و Shared Key Ring بررسی شود.

## حالت اضطراری

در رخداد گسترده، ابتدا کاربران/Scopeهای متاثر مشخص شوند. حذف Key Ring راهکار ابطال نشست نیست؛ این کار همه Cookieها را غیرقابل‌خواندن و بازیابی را دشوار می‌کند.
